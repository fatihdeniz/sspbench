# Converting Novelty Engine Output to aiXamine Benchmark Format

This document explains how to convert questions generated by the Novelty Engine into the standardized benchmark format used by the aiXamine testing pipeline.

## Overview

The conversion process transforms the novelty engine's question format into the aiXamine JSONL format, which is compatible with standard hallucination benchmarks like NQ-Open, TriviaQA, etc.

## Output Format

The converted benchmark follows this schema:

```json
{
  "question_id": "novelty_benchmark_0",
  "question": "What is the capital of France?",
  "target": "Paris",
  "target_aliases": ["paris", "paris, france"],
  "target_type": "paris, paris, france",
  "question_source": "wikipedia",
  "question_source_domain": "European Geography",
  "wiki_title": "Paris",
  "metadata_iteration": 1,
  "metadata_faithfulness": 0.95,
  "metadata_quality_score": 8,
  "metadata_quality_suitable": true,
  "metadata_wiki_url": "https://en.wikipedia.org/wiki/Paris"
}
```

### Required Fields (Standard Format)
- `question_id`: Unique identifier (e.g., "novelty_benchmark_0")
- `question`: The question text
- `target`: Primary answer string
- `target_aliases`: List of acceptable answer variations (normalized, lowercased)
- `target_type`: Comma-separated string of aliases
- `question_source`: Always "wikipedia" for novelty engine
- `question_source_domain`: Category of the question
- `wiki_title`: Wikipedia entity name

### Optional Metadata Fields
- `metadata_iteration`: Which iteration generated this question
- `metadata_faithfulness`: RAGAS faithfulness score (if available)
- `metadata_quality_score`: Quality score 0-10 (if evaluated)
- `metadata_quality_suitable`: Boolean suitability flag
- `metadata_wiki_url`: Source Wikipedia URL

## Usage

### Method 1: Convert by Theme

Load all questions for a specific theme from iteration files:

```bash
./scripts/convert_to_benchmark.sh --theme "science" --iterations 3 \
    --output benchmarks/science_benchmark.jsonl
```

This will:
1. Load `data/novelty/science_iter_1.KI_questions.json`
2. Load `data/novelty/science_iter_2.KI_questions.json`
3. Load `data/novelty/science_iter_3.KI_questions.json`
4. Combine and convert them to benchmark format

### Method 2: Convert Specific Files

Convert one or more specific JSON files:

```bash
./scripts/convert_to_benchmark.sh \
    --input "data/novelty/history_iter_*.KI_questions.json" \
    --output benchmarks/history_benchmark.jsonl
```

Or multiple explicit files:

```bash
./scripts/convert_to_benchmark.sh \
    --input data/novelty/file1.json data/novelty/file2.json \
    --output benchmarks/combined.jsonl
```

### Options

```
--theme THEME           Theme name to load from data/<engine>/
--engine ENGINE         Engine name (default: novelty)
--iterations N          Max number of iterations to include
--input FILE [FILE ...] Input JSON file(s) (supports glob patterns)
--output PATH, -o PATH  Output JSONL file path (required)
--benchmark-name NAME   Benchmark name for question IDs (default: novelty_benchmark)
--no-summary           Skip printing summary statistics
```

## Examples

### Example 1: Convert Recent Science Questions

```bash
# Generate questions first
./scripts/run_novelty.sh --theme "physics" --max-iterations 2

# Convert to benchmark format
./scripts/convert_to_benchmark.sh --theme "physics" --iterations 2 \
    --benchmark-name "physics_bench" \
    --output benchmarks/physics.jsonl
```

### Example 2: Combine Multiple Themes

```bash
./scripts/convert_to_benchmark.sh \
    --input "data/novelty/physics_iter_*.json" \
            "data/novelty/chemistry_iter_*.json" \
            "data/novelty/biology_iter_*.json" \
    --benchmark-name "science_combined" \
    --output benchmarks/science_all.jsonl
```

### Example 3: Python Script Direct Usage

```bash
conda activate autobencher

python scripts/convert_to_benchmark_format.py \
    --theme "history" \
    --iterations 3 \
    --output benchmarks/history.jsonl
```

## Testing with aiXamine

Once converted, use the benchmark with your aiXamine testing scripts:

```bash
# Test with a single model
python aiXamine/test_model.py \
    --benchmark benchmarks/science_benchmark.jsonl \
    --model gpt-4 \
    --output results/science_gpt4.jsonl

# Batch test multiple models
python aiXamine/batch_test.py \
    --benchmark benchmarks/science_benchmark.jsonl \
    --models gpt-4 claude-3 llama-3 \
    --output-dir results/science/
```

## Answer Normalization

The conversion script automatically generates answer aliases:

- **Lowercase normalization**: "Paris" → "paris"
- **Article removal**: "The Beatles" → "beatles", "the beatles"
- **Punctuation removal**: "London." → "london"
- **Numeric formats**: "1,000" → "1000", "1,000"

This improves answer matching during evaluation.

## Troubleshooting

### No files found

```
Warning: No question files found matching pattern: data/novelty/theme_iter_*.KI_questions.json
```

**Solution**: Check that questions were generated first with `./scripts/run_novelty.sh`

### Missing questions or answers

```
Warning: Skipping question 5 - missing question or answer
```

**Solution**: Some questions may be malformed. The script skips invalid entries and reports them.

### Empty output

```
Error: No valid questions after conversion
```

**Solution**: Verify input files contain valid question dictionaries with 'question' and 'gold_answer' fields.

## Integration with Testing Pipeline

The converted JSONL format is directly compatible with:

- **aiXamine hallucination testing**: Standard format for model evaluation
- **Batch testing scripts**: Process multiple models in parallel
- **Analysis notebooks**: Load with pandas for visualization
- **Leaderboard generation**: Compare model performance

```python
# Load in pandas

# Load in aiXamine

```
